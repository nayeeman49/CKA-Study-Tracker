Save the output of `helm history api -n rel` after the rollback to `/opt/answers/helm-history.txt`, and uninstall the release `old-api` from the same namespace while keeping its history.
--- solution ---
```bash
helm history api -n rel
helm rollback api 1 -n rel
helm history api -n rel > /opt/answers/helm-history.txt
helm uninstall old-api -n rel --keep-history

```
A rollback creates a **new** revision (for example revision 4 that copies revision 1), so history gets longer. `--keep-history` leaves the uninstalled release visible with `helm list --uninstalled` or `--all`.

### Q | 6 | Cluster Architecture | cluster1
Create a kubeconfig file `/opt/users/maya.kubeconfig` for the user `maya` that connects to the current cluster (use the cluster name and server from the current kubeconfig) with the client certificate `/opt/users/maya.crt` and key `/opt/users/maya.key`, with a context named `maya@cluster1` set as current. ### Q | 5 | Workloads & Scheduling | cluster1
Create a CronJob `cleanup` in namespace `jobs` that runs every day at 03:30 using image `busybox` and the command `echo cleaning`. Keep the last 2 successful and 1 failed job, do not allow overlapping runs and set `activeDeadlineSeconds` to 120. Trigger a manual run named `cleanup-now`.
--- solution ---
```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: cleanup
  namespace: jobs
spec:
  schedule: "30 3 * * *"
  concurrencyPolicy: Forbid
  successfulJobsHistoryLimit: 2
  failedJobsHistoryLimit: 1
  jobTemplate:
    spec:
      activeDeadlineSeconds: 120
      template:
        spec:
          restartPolicy: OnFailure
          containers:
          - name: c
            image: busybox
            command: ["sh","-c","echo cleaning"]
```
```bash
kubectl apply -f cj.yaml
kubectl -n jobs create job cleanup-now --from=cronjob/cleanup
kubectl -n jobs logs job/cleanup-now
```
A Job Pod must have `restartPolicy` of `OnFailure` or `Never`. `activeDeadlineSeconds` sits under the **job** spec.

### Q | 6 | Workloads & Scheduling | cluster1
Create a Deployment `ha-web` (image `nginx`, 3 replicas) in namespace `ha` so that no two replicas run on the same node. Pods carry the label `app=ha-web`. Use a **required** Pod anti-affinity on the node level. If there are fewer nodes than replicas, the remaining Pods staying `Pending` is acceptable.
--- solution ---
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: ha-web
  namespace: ha
spec:
  replicas: 3
  selector:
    matchLabels:
      app: ha-web
  template:
    metadata:
      labels:
        app: ha-web
    spec:
      affinity:
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchLabels:
                app: ha-web
            topologyKey: kubernetes.io/hostname
      containers:
      - name: nginx
        image: nginx
```
```bash
kubectl apply -f ha.yaml
kubectl -n ha get pods -o wide
```
`topologyKey: kubernetes.io/hostname` makes each node its own domain. The newer alternative is `topologySpreadConstraints` with `maxSkew: 1`, which allows doubling up when needed.

### Q | 5 | Storage | cluster1
Create a PersistentVolume `local-pv` (`10Gi`, `ReadWriteOnce`, storage class `local-storage`, path `/mnt/disks/vol1`) that can only be used on node `node01`. Create a PVC `local-claim` (namespace `ops`, `5Gi`) for it and a Pod `local-app` (image `busybox`, `sleep 3600`) mounting it at `/data`.

  namespace: ops

  storageClassName: local-storage
  accessModes: ["ReadWriteOnce"]
  resources:

      storage: 5Gi
---
apiVersion: v1
kind: Pod
metadata:
  name: local-app
  namespace: ops
spec:
  containers:
  - name: app
    image: busybox
    command: ["sleep","3600"]

    - name: d
      mountPath: /data

### Q | 6 | Services & Networking | cluster1
Pods labelled `app=worker` in namespace `batch` must be able to send traffic **only** to: Pods labelled `app=queue` in namespace `messaging` (port 5672), and CIDR `10.200.0.0/16` except `10.200.5.0/24` (port 443). All other egress, including DNS to CoreDNS Pods in `kube-system` on port 53, must be handled so that name resolution keeps working. Create the NetworkPolicy `worker-egress`.
--- solution ---
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: worker-egress
  namespace: batch
spec:
  podSelector:
    matchLabels:
      app: worker
  policyTypes: ["Egress"]
  egress:
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: messaging
      podSelector:
        matchLabels:
          app: queue
    ports:
    - protocol: TCP
      port: 5672
  - to:
    - ipBlock:
        cidr: 10.200.0.0/16
        except: ["10.200.5.0/24"]
    ports:
    - protocol: TCP
      port: 443
  - to:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: kube-system
    ports:
    - protocol: UDP
      port: 53
    - protocol: TCP
      port: 53
```
Here `namespaceSelector` and `podSelector` are in the **same** item, so they are ANDed (queue Pods in `messaging` only). Policies are additive, so a second policy can add more allowed traffic but never subtract.
